# Negative controls for every automated gate (Card M2)

## Findings

1. **Four formerly-`VACUOUS` gates and `F-054` were closed on trunk by PR `#197` (`427a0e6`, merged `03b9d3d`) and now genuinely `CATCHES`:**
   - `thread_rng_scan` (`.github/workflows/hardening.yml:75-76`) now catches imported `thread_rng()`, `ThreadRng`, and `rand::rng` across `src-tauri/src` and `src-tauri/crates` (`exit = 1`).
   - `check_test_targets_unscheduled` (`.github/workflows/ci.yml:192`) now passes `--profile desktop` and catches dropped `--features desktop` (`exit = 1`).
   - `ci_ipc_arg_case` (`.github/workflows/ci.yml:330`) now runs `npm run check:ipc` in the Frontend job and catches snake_case `invoke(...)` arguments (`exit = 1`).
   - `ci_e3` (`.github/workflows/ci.yml:326`) now runs `npm run check:e3` in the Frontend job and catches tampered E3 `effects.json` (`exit = 1`).
   - `check_bundle` (`scripts/check_bundle_budget.mjs:111,263`) now inspects chunk contents via `THREE_D_CONTENT` / `hasThreeJsSignature` alongside `THREE_D_CHUNK`, catching `three` in `dist/index.html` regardless of chunk filename (`F-054`).
2. **`conflict_marker_scan` is `NOT RUN (no automated gate)` on trunk `e576350`.** Planned in `CARD M2` (`docs/ai/planning/2026-11-05-swarm-prompts.md`), with no automated check merged into `e576350` yet (implemented separately in PR `#210` `mac/gate-conflict-marker-scan`).
3. **Five Windows-only licensing / SBOM / `NOTICE` gates are `NOT RUN (not measured on Windows)`:** `ci_licenses_complete`, `check_licenses_complete`, `check_licenses`, `check_sbom`, and `check_notice`. Committed licensing/SBOM/`NOTICE` artifacts track the Windows CI dependency graph (`cargo tree --features desktop`, `.github/workflows/ci.yml:210-213`), so they cannot be measured cleanly on macOS.
4. **Two full-suite gates remain `NOT RUN (time)`:** `cargo_test_desktop_full` and `hardening_stability_5x` exceed the 30-minute-per-fault harness ceiling on quiet hardware (targeted Rust suites cover those fault paths in seconds, and quiet-machine single-run baselines are recorded below).

## Command to reproduce

From the repository root with a clean git working tree, `node_modules` and `tests/node_modules` installed, pinned Rust toolchain (`1.98.1`), `cargo-audit`, `cargo-deny`, `cargo-modules`, and `python3` available:

```bash
node scripts/paper/gate_controls.mjs
```

Individual controls can be inspected with `--gate <id1>,<id2>`, registered gates listed with `--list`, and built-in classification/registry checks run with `--self-test`. Each control first verifies a clean detached worktree baseline under `os.tmpdir()` (reporting `NOT RUN (baseline red)` without running the fault patch if the clean baseline exits non-zero, or `NOT RUN (not measured on Windows)` on non-Windows hosts for `windowsOnly` gates), then applies a single patch from [`scripts/paper/gate_faults/`](../../../scripts/paper/gate_faults/) in a fresh detached worktree and verifies both `exit != 0` and a match against `gate.matchers` (which must not match clean-baseline output) before awarding `CATCHES`. CI commands and step definitions are extracted dynamically from `.github/workflows/ci.yml` and `.github/workflows/hardening.yml` wherever the CI step completes within the per-fault budget; narrowed Rust subsets using CI's extracted features are labeled `[harness-assembled]`.

## Scope and limitations

- Measured on macOS (`arm64`) at PR `#196` head `1fd25eb` (full 62-gate baseline) and `12a3cf1` (16-gate Round 2 re-measurement: `ts_rs_parity`, `check_test_targets_unscheduled_profile`, `cargo_test_worldgen`, `feature_gated_targets`, `schedule_ambiguity_simrng`, `schedule_ambiguity_energy`, `zero_alloc`, `closed_eu`, `live_experiment_fork`, `live_experiment_saveload`, `determinism_golden_hash`, `verify_dataflow`, `cargo_deny`, `eslint_ratchet`, `check_bundle`, `playwright_e2e`) with merged trunk `e576350`; the follow-up commit changes only display labels and metadata text. Five `windowsOnly` compliance gates (`ci_licenses_complete`, `check_licenses_complete`, `check_licenses`, `check_sbom`, `check_notice`) are marked `NOT RUN (not measured on Windows)` rather than tested on macOS because their committed artifacts reflect Windows CI's `cargo tree --features desktop` graph (`.github/workflows/ci.yml:210-213`).
- Standalone verification scripts `scripts/verify_sel2p_artifacts.mjs` and `scripts/verify_esel1_artifacts.mjs` exist in `scripts/` without entries in `package.json` or `.github/workflows/ci.yml` and are outside the `ci.yml` / `package.json` gate inventory covered here.
- `check_test_targets_empty`, `check_test_targets_ignored`, `check_test_targets_unscheduled`, and `check_test_targets_unscheduled_profile` run the 12 policy test targets plus `--workspace --doc` (`POLICY_TEST_TARGETS` in `scripts/paper/gate_controls.mjs`) rather than all 150+ desktop targets because full all-target desktop compilation/testing exceeds 30 minutes per fault.
- Similarly, the 7 targeted Rust controls (`feature_gated_targets`, `schedule_ambiguity_simrng`, `schedule_ambiguity_energy`, `zero_alloc`, `closed_eu`, `live_experiment_fork`, `live_experiment_saveload`) are marked `[harness-assembled]`: they extract CI's `--features desktop` flag from `.github/workflows/ci.yml` dynamically via `extractCiCargoTestFeatures` and narrow `cargo test` to the single affected `--test <target>` binary because the full `cargo test --features desktop` step is `NOT RUN (time)`.
- `verify_dataflow` executes the `.github/workflows/hardening.yml` step verbatim, which runs `cargo install cargo-modules` on the host if `cargo-modules` is not already installed.
