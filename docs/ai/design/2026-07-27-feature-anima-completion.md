## 1. Map manifest becomes evidence (R1, R2)

### The two manifests are different documents, and conflating them is the trap

There are two manifest formats in this repository and they are **not** versions of one another:

| File | Schema | Tracked? | Consumer |
|---|---|---|---|
| `map_manifest.json` | `map_manifest.schema.json` (project-local, `schemaVersion` is a **number**) | yes | `src/components/Landscape/utils/mapManifest.ts`, test S05 |
| `animal-map.manifest.json` | the MCP's `animal-map-manifest.schema.json` (`schemaVersion` is a **string**) | **no** — gitignored, regenerated by `npm run gen:manifest` | `animal-map-vision` MCP gates |

Verified 2026-07-27: `validate_map_manifest` pointed at `map_manifest.json` returns
`critical / invalid-manifest — schemaVersion: Invalid input: expected string, received number`.
That is not a defect in either file; it is the MCP correctly refusing a document written to a
different schema. **Do not "fix" `map_manifest.json` by making `schemaVersion` a string** — that
would break the project-local validator and test S05 to satisfy a validator that was never pointed
at it. The MCP gate runs against the generated `animal-map.manifest.json`, which
`scripts/gen_map_manifest.ts` already emits in the MCP schema from the real world generator.

### Mechanism

`map_manifest.json` becomes **generated, not hand-authored**, by a new
`scripts/gen_world_manifest.ts` that:

1. runs the real frontend `generateWorld` at the backend's actual working resolution;
2. encodes it with the real `worldToArtifact` encoder (the same one whose byte-equality with the
   Rust decoder is already gated) and writes `artifacts/world_<dim>.anmw`;
3. computes the **real** SHA-256 of those bytes;
4. emits the manifest with that checksum, that path, and that `gridDim`.

The artifact is a build output and is gitignored alongside `animal-map.manifest.json`; the manifest
stays tracked because the project-local validator and the coordinate contract both read it.

Test S05 splits into two tests with different jobs:

- the existing **pure** test keeps its inline fixtures — its job is to prove the *validator* rejects
  malformed input, and it must stay free of `fs` so it can run in the strict pure-test environment;
- a new **evidence** test loads the committed `map_manifest.json` from disk, runs the validator on
  it, and then asserts the physical facts: the artifact file exists, its SHA-256 equals the declared
  checksum, its ANMW header width/height equal the declared `width`/`height`, and the declared
  `gridDim` equals the backend default. This is the test that would have caught A1.

### Views: what is provable here and what is not

The eight canonical views are perspective captures of a 3D mesh. The repository has no capture
pipeline (`scripts/gen_map_manifest.ts` says so in its own header for `pipeline.panorama`), and
CLAUDE.md forbids running the full backend on this machine. A capture path exists in principle —
Playwright drives real Chromium WebGL against `landscape.html` — but building it is a feature, not
a hardening step, and a screenshot produced by a harness nobody has validated is not better
evidence than an honest absence.

Design decision: **the manifest stops claiming captured images it does not have.** Each view keeps
its camera specification (that *is* real: it is the contract for what a future capture must shoot)
and gains an explicit `captured: false`. The evidence test asserts the invariant that actually
matters — *every view claiming `captured: true` must have a file on disk* — so the day a capture
pipeline lands, the gate is already watching it. Fabricating eight PNGs to make a green check is
the failure mode this whole pass exists to remove.

## 2. Grid dimension (R4, R5)

`DEFAULT_GRID_DIM` is not deleted, because `sim_rules.rs` is the units/contract table and the
documents cite it by name. It is **corrected to 256** and given a doc comment that names
`MapSettings::default()` as the thing it must track.

A drift guard is the actual fix: an assertion that `DEFAULT_GRID_DIM == MapSettings::default().width
== MapSettings::default().height`. The constant went stale precisely because nothing tied it to the
value it claimed to mirror; correcting the number without tying it down leaves the same trap armed.

Documents corrected: `COORDINATE_CONTRACT.md` §4 (the `1.5625` row), `SIMULATION_RULES.md` §5,
`MAP_MANIFEST.md`, `BENCHMARK_BASELINE.md` (the open finding is resolved and recorded as resolved),
and `map_manifest.json` via its generator.

R5 is served by property tests over the transforms at 1×1, 2×2, 127×127, 128×128, 256×256, 1024×1024
and non-square dimensions, asserting: every cell centre round-trips to its own cell; corner cells
map inside bounds; a point on the max edge buckets to the last cell rather than out of range; and
`world_xz_to_cell` returns `None` strictly outside bounds.

## 3. Security (R6, R7, R8)

### CSP

`security.csp` moves from `null` to an explicit policy. It must be compatible with what the app
actually does: Vite injects styles at runtime (`style-src` needs `'unsafe-inline'`), the app loads
WASM/workers for the renderer, and Tauri's IPC uses `ipc:`/`asset:` custom schemes. The policy is
derived from observed usage, not copied from a template — a CSP that breaks the app gets reverted
by the next person and leaves the surface open again.

### Save/load paths

The frontend passing an arbitrary `String` path is the finding. The fix is a **least-privilege
contract**, not a blocklist: saves resolve inside the app-data directory, the command takes a
*save name* rather than a path, and any name that escapes the directory after canonicalisation is
refused. A migration reader keeps existing absolute-path saves loadable so the change does not
strand users' worlds — that path is read-only and explicitly opt-in.

### `unsafe impl Send/Sync`

The proof obligation is real: `BrainModel` owns a `WgpuDevice`. Order of preference is (1) remove
the `unsafe` if the underlying types are in fact `Send + Sync` today, (2) encapsulate, (3) prove.
This is determined by reading burn 0.13's bounds, not assumed.

## 4. Lineage cumulative mutations (R9)

Exactly as [§3.15.1](../../planning/STATE_OF_THE_PROJECT.md) specifies, and for the reason it gives:
the field is `Option<u32>`, not `u32`, because `LineageNode` is inside `SavedSimulationState` and a
defaulted `0` reads as *"this lineage never mutated"* for every historical save — finite, plausible,
wrong. `None` means "not recorded, walk the edges as before".

Order matters and is not negotiable: the count lands and is proven equal to the edge-walk **first**;
only then does `compact` switch to `compress_unary_paths: true`. Reversing the order is what makes
the UI number silently wrong.

## 5. Licensing and inventory (R10)

`NOTICE` is generated from the actual dependency graph of the shipped configuration
(`--features desktop`), not from `Cargo.toml`'s direct dependencies — attribution obligations
follow what is distributed, which includes transitive crates. `LICENSE` gains an explicit scope
section separating code / model weights / datasets / assets.

## 6. ESLint (R11)

Warnings are fixed, never suppressed. `any` in production code is replaced with real domain types —
in most cases the generated `ts-rs` types already exist and the `any` is there because nobody wired
them up, which makes this work overlap with the IPC-parity requirement. The ratchet baseline is
lowered to match; it is never raised.

## Risk register

| Risk | Mitigation |
|---|---|
| CSP breaks the app in a way tests do not catch (tests run under jsdom, not the Tauri webview) | Derive from observed usage; keep the policy in one place with a comment naming each directive's reason; E2E navigation smoke covers the Vite path |
| Path-constraining save/load strands existing saves | Read-only migration path for absolute paths, tested |
| Enabling lineage compression changes a UI number | Two-sided test comparing pre- and post-compression counts on the same fixture, landing *before* the flip |
| Touching `sim_rules.rs` perturbs a determinism checksum | `DEFAULT_GRID_DIM` is read nowhere in `src/`; verified by grep before the edit and by the full suite after |
